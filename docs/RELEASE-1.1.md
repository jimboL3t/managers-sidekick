# Ιστορικό, διαθεσιμότητα και εγκατάσταση — 1.1.0

[English](RELEASE-1.1.en.md)

## Ιστορικό

Στο ημερολόγιο πατήστε **Ιστορικό → Στιγμιότυπο μήνα** και δώστε περιγραφή, π.χ. «Δημοσιευμένος Οκτώβριος». Αποθηκεύονται ο συγκεκριμένος μήνας και τα τότε ονόματα, ωράρια, κανόνες, δεξιότητες, διαθεσιμότητα, άδειες, αργίες, αναθέσεις και λουκέτα. Πριν από κάθε υπολογισμό, μαζί με το **Άλλος συνδυασμός**, αποθηκεύεται αυτόματα στιγμιότυπο. Οι μελλοντικές αλλαγές δεν μεταβάλλουν αυτά τα αντίγραφα.

Επιλέξτε εγγραφή για **Προβολή**, **Εξαγωγή PDF** με τις παλιές ρυθμίσεις ή **Επαναφορά ως νέα ομάδα**. Η επαναφορά δημιουργεί ανεξάρτητη δοκιμαστική ομάδα μόνο με αυτόν τον μήνα, χωρίς αντικατάσταση της ενεργής ομάδας. Το ιστορικό βρίσκεται μέσα στο `data/sidekick.json`, χωρίς αυτόματη λήξη· μεγαλώνει το αρχείο όσο προστίθενται στιγμιότυπα. Διαγραφή ομάδας διαγράφει και το ιστορικό της, ενώ αντίγραφο ομάδας κρατά ανεξάρτητο ιστορικό.

Δεν πρόκειται για καταγραφή κάθε κλικ ή πλήρη αναίρεση. Δεν ανακτά παλιές ρυθμίσεις από εποχές πριν δημιουργηθεί στιγμιότυπο. Κρατήστε ονομαστικό στιγμιότυπο όταν δημοσιεύετε ή πριν σημαντικές χειροκίνητες αλλαγές. Το κανονικό ημερολόγιο και τα ετήσια σύνολα συνεχίζουν να χρησιμοποιούν τρέχουσες ρυθμίσεις· η παγωμένη έκδοση βρίσκεται στο Ιστορικό.

## Διαθεσιμότητα

Πατήστε **Διαθεσιμότητα**, επιλέξτε εργαζόμενο και τις διαθέσιμες ημέρες εβδομάδας. Αρχικά όλες είναι διαθέσιμες, και για παλιούς εργαζομένους. Στις εξαιρέσεις βάλτε μία ημερομηνία ανά γραμμή:

```text
2026-10-05=0
2026-10-10=1
```

Το `0` αποκλείει εργασία και το `1` την επιτρέπει, υπερισχύοντας του εβδομαδιαίου μοτίβου. Οι ημερομηνίες έχουν μορφή YYYY-MM-DD χωρίς διπλοεγγραφές. Κενό πεδίο εξαιρέσεων αφαιρεί τις εξαιρέσεις. Η πρώτη υλοποίηση αφορά ολόκληρες ημερομηνίες, όχι ωριαία διαθεσιμότητα ή συμβάσεις.

Ο αλγόριθμος αποκλείει εργασία σε μη διαθέσιμες ημέρες, και για συμπληρωματικές βάρδιες. Νυχτερινή βάρδια ελέγχει και την επόμενη ημερομηνία όταν τελειώνει μετά τα μεσάνυχτα. Λήξη ακριβώς 00:00 δεν δεσμεύει την επόμενη ημέρα. Χειροκίνητες επιλογές και λουκέτα διατηρούνται, με παρατήρηση αν συγκρούονται. Δεν γίνεται αυτόματος επανυπολογισμός στην αλλαγή διαθεσιμότητας.

Η μη διαθεσιμότητα δεν είναι άδεια ούτε μειώνει μόνη της τον στόχο εργασίας. Μπορεί να δοθεί ρεπό μέχρι τη μηνιαία ποσόστωση. Αν οι διαθέσιμες ημέρες δεν αρκούν, αναφέρεται η απόκλιση. Πραγματικές άδειες καταχωρίζονται ξεχωριστά.

## Installer με ενσωματωμένη Java

Το `scripts/package_native.py` χρησιμοποιεί `jpackage`/`jlink` του JDK για να ενσωματώσει Java. Στον υπολογιστή που λαμβάνει native πακέτο δεν απαιτείται ξεχωριστή Java. Η γραμματοσειρά PDF παραμένει απαίτηση του λειτουργικού.

```sh
python3 scripts/package_native.py --type app-image
# Σε macOS
python3 scripts/package_native.py --type dmg
# Σε Windows
python scripts/package_native.py --type exe
# Σε Linux
python3 scripts/package_native.py --type deb
```

Κάθε build γίνεται στο αντίστοιχο OS/CPU: δεν δημιουργούμε Windows installer από το Mac. Χρειάζονται JDK 21+ με jpackage/jlink, Maven, Python και τα εργαλεία πακεταρίσματος του OS. Για Windows απαιτείται συμβατό WiX με το επιλεγμένο JDK, για Linux τα εργαλεία deb/rpm. Βλ. [επίσημο οδηγό jpackage](https://docs.oracle.com/en/java/javase/25/jpackage/packaging-overview.html). Η έξοδος είναι στο `dist/native-<os>-<architecture>-1.1.0-<type>`. Δεν αντικαθίστανται υπάρχοντες φάκελοι εξόδου.

Το `app-image` είναι έτοιμος φάκελος εφαρμογής, όχι installer· μεταφέρεται ολόκληρος. Το macOS πακέτο ανάπτυξης δεν είναι υπογεγραμμένο/notarized. Απαιτούνται έλεγχοι εγκατάστασης και αναβάθμισης ανά πλατφόρμα πριν ευρεία διανομή. Windows/Linux πακέτα πρέπει να παραχθούν και να δοκιμαστούν στα αντίστοιχα συστήματα.

### Δεδομένα εγκατεστημένης εφαρμογής

Τα native πακέτα γράφουν στο **`<φάκελος χρήστη>/ManagersSidekick/data/sidekick.json`**, π.χ. `C:\Users\Όνομα\ManagersSidekick\data` στα Windows. Το φορητό ZIP κρατά το παλιό `data` δίπλα στο JAR. Προαιρετικά `-Dsidekick.dataDir=/διαδρομή` ορίζει άλλον φάκελο. Η ένδειξη αποθήκευσης εμφανίζει πλέον την πλήρη διαδρομή.

Δεν γίνεται αυτόματη μεταφορά ή συγχώνευση: αποθήκευση, κλείσιμο, backup του παλιού `data` και αντιγραφή του στη νέα θέση. Κρατήστε αντίγραφο υπάρχοντος προορισμού πριν αντικατάσταση. Όλες οι native εκδόσεις του ίδιου χρήστη μοιράζονται τη θέση· όχι ταυτόχρονη εκτέλεση. Η αναβάθμιση εφαρμογής δεν είναι επαναφορά δεδομένων. Οι οδηγίες παρέχονται και στο φορητό ZIP.

## Πρόταση δικαιότερης κατανομής — δεν υλοποιήθηκε στην 1.1

Η προτεινόμενη ρύθμιση ομάδας θα έχει ξεχωριστούς στόχους νυχτερινών/Σαββατοκύριακων, βάρη προτεραιότητας, μήνες αναφοράς και σαφή χαρακτηρισμό νυχτερινής υπηρεσίας. Ανά εργαζόμενο θα επιλέγεται συμμετοχή σε κάθε στόχο. Εξαίρεση από εξισορρόπηση δεν σημαίνει απαγόρευση νύχτας· αυτή χρειάζεται ξεχωριστό αυστηρό κανόνα.

Δίκαιοι στόχοι πρέπει να λαμβάνουν υπόψη δεξιότητες, διαθεσιμότητα και συμβάσεις, όχι απλώς ίδιους αριθμούς για όλους. Ο αλγόριθμος θα κρατά χειροκίνητες επιλογές/λουκέτα, θα εμφανίζει μετρήσεις πριν/μετά και θα προσπαθεί να μειώσει τις αποκλίσεις. Κάλυψη, ανάπαυση και διαθεσιμότητα προηγούνται· η δικαιοσύνη είναι προτίμηση βελτιστοποίησης, εκτός αν οριστεί ρητό ανώτατο όριο. Η σημερινή έκδοση δεν εξισορροπεί ξεχωριστά νύχτες και Σαββατοκύριακα.

## Προεπισκόπηση, αναίρεση και πολλαπλά backup

Σήμερα αλλαγές κελιών και υπολογισμοί αποθηκεύονται αυτόματα. Το να μην πατήσετε Αποθήκευση δεν προστατεύει την προηγούμενη κατάσταση. Η αληθινή προεπισκόπηση θα υπολόγιζε σε ξεχωριστό προσωρινό αντίγραφο με **Αποδοχή/Απόρριψη**. Η αναίρεση θα επέστρεφε πρόσφατη εφαρμοσμένη αλλαγή. Πολλαπλά χρονολογημένα backup θα προστάτευαν ολόκληρο το αρχείο ανεξάρτητα από το εσωτερικό ιστορικό και το μοναδικό `.bak`. Παραμένουν προτάσεις, όχι νέα κουμπιά της 1.1.
